# ARDOR Battery для Linux

[English](README.md)

Нативная утилита чтения заряда и трей KDE Plasma 6 для
**ARDOR GAMING Phantom PRO V2**. Проверена владельцем на Fedora, Plasma 6,
Wayland — через приёмник 2.4 ГГц и USB-кабель.

- Нейтральные цифры на прозрачном фоне, цвет из темы рабочего стола.
- Обновление раз в 30 секунд и вручную через меню.
- Режим подключения, подробности ошибок и время последнего успешного чтения.
- Русский и английский интерфейс, выбор языка сохраняется.
- Уведомления о низком заряде — по желанию, изначально выключены.
- Запуск без root после установки точечного правила udev.

Проект неофициальный. Другие модели пока не поддерживаются и не опрашиваются.

## Установка

Нужны Linux, Python 3.10+ и графический сеанс с системным лотком
StatusNotifierItem. Проверено на Plasma 6 Wayland. Для трея нужен Qt,
терминальная утилита использует только стандартную библиотеку Python.

### Зависимости

| Уровень | Требования |
| --- | --- |
| CLI | Python 3.10+, Linux hidraw/sysfs и доступ к устройству; pip-пакеты не нужны |
| Трей | PySide6 Essentials; shiboken6 нужной версии и Qt-компоненты wheel устанавливаются автоматически |
| Рабочий стол | Нативные библиотеки Qt, шрифты, сеансовый D-Bus и лоток StatusNotifierItem; проверено на Plasma 6 |
| Права на устройство | udev + logind для нашего правила uaccess активного сеанса |
| Автозапуск | Пользовательский systemd и systemctl |
| Только диагностика | usbutils для lsusb, acl для getfacl; hidapi необязателен |

Установите Python для своего дистрибутива; sudo должен быть уже настроен.

**Fedora:**

```sh
sudo dnf install python3 python3-pip
```

**Debian / Ubuntu / Kubuntu / Linux Mint и совместимые производные:**

```sh
sudo apt update
sudo apt install python3 python3-pip python3-venv
```

Необязательные команды диагностики: `sudo dnf install usbutils acl` в Fedora
или `sudo apt install usbutils acl` в Debian/Ubuntu.
Это не установка рабочего стола. Инструкции Debian/Ubuntu пока не проверены
на оборудовании; проверенная среда — Fedora KDE. Трею нужен лоток
StatusNotifierItem: установка пакетов сама по себе не добавляет его в любой
сеанс GNOME или другого рабочего стола.

[Полный список зависимостей](docs/dependencies.ru.md): библиотеки Wayland/XCB,
проверенные версии, системные команды и диагностика плагинов Qt.
Одного requirements.txt недостаточно для описания всей системы.

### Python-пакеты

Скачайте или клонируйте репозиторий и откройте его каталог:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Доступ активному локальному сеансу только к **3554:F52D/F52E, интерфейс 01**:

```sh
sudo install -m 0644 udev/70-ardor-battery.rules /etc/udev/rules.d/70-ardor-battery.rules
sudo udevadm control --reload-rules
```

После установки физически переподключите приёмник и кабель мыши.
Глобальные права на HID не выдаются.

```sh
.venv/bin/python ardor.py --read --json
.venv/bin/python ardor_tray.py
```

Трей запускается от обычного пользователя, без sudo.

## Язык

Правая кнопка по значку → **Язык → Как в системе / English / Русский**.
Выбор применяется сразу и сохраняется. Автоматически выбирается русский для
русской локали, иначе английский. Для одного запуска:

```sh
.venv/bin/python ardor_tray.py --language ru
.venv/bin/python ardor_tray.py --language en
```

CLI и технические подробности ошибок — на английском. Ключи JSON не меняются.

## Автозапуск

Закройте вручную запущенный трей через «Выход». Из каталога проекта выполните:

```sh
.venv/bin/python install.py --enable
```

Установщик создаёт пользовательский сервис, ярлык меню приложений и
`~/.local/bin/ardor-battery`, подставляя пути текущего проекта и его Python.
Он не копирует исходники, не устанавливает зависимости и не меняет udev.
Не удаляйте каталог проекта и venv; после переноса повторите установку.
`install.py --dry-run` показывает результат без записи файлов.
Шаблоны из `systemd/` и `desktop/` напрямую копировать не нужно.

Если раньше добавляли `~/.config/autostart/ardor-battery.desktop`, уберите именно
этот ярлык оттуда, чтобы не было двух способов автозапуска. Автоматически он не удаляется.

```sh
systemctl --user status ardor-battery.service --no-pager
systemctl --user restart ardor-battery.service
journalctl --user -u ardor-battery.service -b -n 50 --no-pager
```

Сервис следует за графическим сеансом, перезапускается после ошибки.
Пункт «Выход» завершает программу штатно: повторный запуск — при следующем
входе либо по команде start. Linger и системный сервис не нужны.

Отключить автозапуск:

```sh
systemctl --user disable --now ardor-battery.service
```

## Поведение и ограничения

При подключённом кабеле проводной интерфейс имеет приоритет. Путь HID
определяется заново при каждом чтении, descriptor проверяется. Отправляется
один известный запрос батареи. Команды DPI, частоты опроса, профилей и прошивки
не используются. USB reset и отсоединение драйверов не выполняются.

При таймауте значок показывает `?`; прошлое значение остаётся только в подсказке
как последнее успешное чтение с временем. Таймаут не различает сон,
выключение мыши и недоступность связи.

**Проценты по кабелю и приёмнику различаются**: например, 40% по USB и 30%
сразу после отключения кабеля. Выводится значение устройства без коррекции.
Независимая точность процентов не установлена. Флаг кабеля не считается
доказательством активной зарядки.

Уведомления включаются в меню. Пороги 20/10/5% требуют двух последовательных
успешных низких показаний через приёмник при сброшенном флаге кабеля.
Каждый порог срабатывает один раз; беспроводное показание выше 25% разрешает
повтор. Ошибки и кабель прерывают подтверждение. Доставка зависит от настроек
Plasma и режима «Не беспокоить».

Настройки хранятся через QSettings в `ardor-community/battery-tray` в конфиге
пользователя. `--interval 60` меняет интервал на минуту; минимум — 10 секунд.

## Диагностика

```sh
.venv/bin/python ardor.py --diagnose
lsusb -d 3554:
```

Диагностика пассивная. Необязательный hidapi используется только для
дополнительного перечисления. Нулевые Usage его libusb backend не мешают:
утилита читает descriptor из sysfs.

При ошибке доступа возьмите актуальный путь hidraw из диагностики:

```sh
udevadm info --query=property --name=/dev/hidraw4 --no-pager
getfacl /dev/hidraw4
loginctl list-sessions --no-pager
```

Проверяйте `ARDOR_BATTERY_RECEIVER=1`, тег `uaccess` и ACL активного пользователя.
Перезагрузка правил не меняет уже подключённое устройство — переподключите его.
При обрывах проводного соединения сначала проверьте другой кабель передачи
данных и USB-порт без запуска утилиты. В ходе тестирования причиной был кабель.

## Другие модели мышей

На оборудовании проверена только Phantom PRO V2. Для добавления другой модели
откройте issue: точное название, VID/PID приёмника и кабеля, пассивная диагностика
`--diagnose`, источник протокола или ссылка на официальное ПО. Для совместимого
протокола может хватить небольшого профиля, но необходима проверка владельцем.
См. [CONTRIBUTING.md](CONTRIBUTING.md); неизвестные устройства вслепую не опрашиваются.
